The non-functional requirements,
from the inside

NFRs — non-functional requirements — is this project's own operative term for version control, reliability, resilience, security, backups, consistency, explainability, and documentation. That sentence was written a month before this site was conceived, and it is the site's table of contents. Other sites in this network sell the argument that somebody has to be the villagers. This one is the same sentence from the inside: how the NFRs actually get done here, including where they do not.

The topic map → The scorecard, unsoftened → Why these sites are agent memory →

“What I call the non-functional requirements, which fundamentally is the whole version control, reliability, resilience, security, backups, consistency, explainability, and documentation.”

Quoted verbatim wherever this site states its scope, because the scope is the quote. Eight items. This site owns the disciplines among them that have no other home, links the ones that do, and publishes the fact that the eighth — backups — has no doctrine written anywhere.

This is a hub, and it behaves like one

Most of the topics on that list already have an owner somewhere in the network. A hub that restates what its spokes measured is worse than no hub, so this one has a rule it enforces in CI rather than in prose.

The ruleWhat it means here
Link the measurement, never restate itWhen a sibling site has measured something, this site links that page. It does not re-measure and does not paraphrase the number.
Generate or date every numberEvery figure on this site carries an as-of date or is generated at build time. The pre-release gate rejects a page that carries figures without one.
Every discipline page ends with its counter-evidenceA page teaching a practice closes with the measured places that practice failed here.

The stakes are raised by the memory thesis: if these sites are memory an agent reads, a stale page is not an inconvenience, it is a false memory. The freshness discipline and the thesis arrive together or not at all.

The estate, measured against its own eight-item list

A site teaching NFRs from an estate whose scorecard is mixed is credible in a way no clean-room guide is. A clean column would be dishonest. Every lapse below is already published in a sibling pack with its evidence — this site adds assembly, not exposure.

NFRThe estate, measured as of 24 Aug 2026
Version control✅ auto-increment tags, the version file convention, a hundred days of dense history
Reliability / resilience✅ watchdog, health poller, bake-and-verify — and a dead workflow invoking a binary defined nowhere, sixteen times, that nobody noticed
Security✅ key discipline, deny-by-default allowlists — and one disclosed key-in-history incident, handled well
Backups⚠️ the thinnest topic in the corpus: mentioned constantly, no doctrine anywhere
Consistency🟡 total banner compliance beside partial import alignment; four stale sources of truth
Explainability✅ reality docs, provenance — and no evals anywhere
Documentation✅ a governing rule and a corpus over a million words — and a README describing a repository that does not exist

Seven rows for eight NFRs: reliability and resilience are one row because the corpus uses them interchangeably. The full table, with every cell linked to the sibling pack holding its evidence and the numbers left where they were measured, is on the scorecard.

Why a website, and not a memory feature

The clearest statement of what this whole network is for was made in a chat message, and it belongs on a page.

“The idea of these sites is to provide good briefs for agents to learn about how we work and think — these sites are a more evolved and focused version of what is usually called LLM memory.”

Conventional memory is accumulated transcripts, retrieved by similarity, private to one vendor, unversioned and invisible to the person it describes. This is the same function built as publishing: memory you can read, cite, version, license and hand to any agent, because it is a website.
